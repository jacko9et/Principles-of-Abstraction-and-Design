# Origin Language 语义设计

> 定位：语义层 = 语言环境提供的**原子操作**及其解释——每个原子操作作用于什么值、发生什么作用、产出什么、失败时如何响应。本文档回答「原子操作各自做什么」。

## 定位与范围

- 语义层是语言环境的设计：定义原子操作与它们的解释；
- 四元落点：每个原子操作是**操作**（操作也是值）；其解释 = 环境对操作的解释；
- 与既有文档的衔接：
  - 《语言结构设计》「最小操作集合」的结构操作（`=` 绑定 / lambda / 函数声明 / 字段访问 / if / 顺序结构 / 类型声明 / 实例构造与方法调用 / 失败捕获 / 返回 / 循环），不在本文档重复；
  - 《类型系统设计》弱类型模式一章的「骨架边界」遗留的「各原子操作的具体解释表」在此落地；
  - 操作解释规则模式无关（《类型系统设计》「操作解释规则模式无关」）——每个原子操作的解释不因强 / 弱类型模式而变；
  - 操作文本形态：操作名是名称（《语法设计》「操作名的文本」），无关键字。

## 最小原子操作集合

### 1. 算术操作

- 操作名：`+` / `-` / `*` / `/`——中缀连接操作（《语法设计》「文本环境对这些值的解释」第 6 条），形态 `x + y`（解释顺序见语法层）；
- 解释：作用于**同类数值对**——两个 int → int、两个 long → long、两个 double → double、两个 float → float（操作自行解释，《类型系统设计》『弱』的定性）；byte 是字节数据单位，不参与算术；
- `-` 的解释 = 两个同类数值的差（二元）；一元负数不在最小解释规则内——负数表达可在后续版本中细化；
- 混合类型（如 int 与 long）不在解释规则内 → 操作无法完成作用 → 诊断值（见后文「操作失败的统一响应」）——与「数值类型间无隐式关系」（《类型系统设计》「类型关系判定的机制」）一致；
- 失败情形：`/` 除零；溢出（结果超出对应类型的精度——int / long 精度由配置策略决定，《类型系统设计》「原子类型值」）；
- `+` 的另一解释：作用于两个 String → 拼接产出 String（Java 习惯）；String 与数值混合不在解释规则内 → 诊断值（不设隐式转换，《类型系统设计》『弱』的定性 不转换）；
- 失败响应见后文「操作失败的统一响应」。

### 2. 比较操作

- 操作名：`==`（相等判定）、`<`（小于）、`>`（大于）——中缀连接操作（《语法设计》「文本环境对这些值的解释」第 6 条），形态 `a == b` / `a < b` / `a > b`；
- `==` 的解释——作用于**任意两个值**：
  1. 先判定两个值的**可区分性**：若两个值**不可区分**（就是一个值），载荷必然相同，产出 true，不再比较载荷；
  2. 若两个值**可区分**（是两个值），再比较它们的**载荷**：载荷相同产出 true，载荷不同产出 false；
  - 「载荷」 = 值的承载内容：对 int 是数值、对 String 是字符序列、对结构是结构形态——各类值的载荷比较由环境的解释提供；
  - Unknown 只是「无法解释」的标记，与普通值没有本质区别——所有值都有其承载内容；
- `<` / `>` 的解释：作用于两个同类的数值（int / long / double / float），按数值序判定，产出 boolean；混合类型不在解释规则内 → 诊断值（见后文「操作失败的统一响应」）；byte 的相等用 `==`（已通用）；
- 与类型系统的衔接：`==` 作用于任意值，其操作声明是参数化的（《类型系统设计》「类型构造操作」）；
- 失败情形：无（任意两个值都可完成 `==` 判定；任意两个同类数值都可完成 `<` / `>` 判定）；
- 必需性：必需——比较是 if 条件的 boolean 来源。

### 3. 转换：类型值可应用

- 形态：`int(x)` / `long(x)` / `float(x)` / `double(x)` / `byte(x)` / `String(x)`——`int` 等是**类型值**（《类型系统设计》「原子类型值」），类型名后紧邻参数括号时，环境对它的应用解释 = **转换**（与实例构造 `Person("Jack")` 同一形态，《语言结构设计》「实例构造与方法调用」）；
- 机制落点：转换不是独立操作，是**一条环境解释规则**——数值与 String 原子类型值可应用。类型值仍是值（类型也是值，《类型系统设计》「类型宇宙的骨架」），名字 `int` 绑定的是同一个类型值——它在应用位置被环境解释为转换，不引入第二个 `int`；
- 可应用边界：
  - **数值原子类型值**（int / long / float / double / byte）可应用：作用于任意数值类型 → 数值转换；作用于 String → **解析**（`int("42")` 产出 42，解析失败 → 诊断值，见后文「操作失败的统一响应」）；
  - **String 类型值**可应用：作用于**任意值** → 该值的字符串表示（`String(42)`、`String(x)`（x 为经 `s.at(n)` 得到的 char 值）、`String(true)`）；幂等：`String(s)` 对已为 String 的 s 产出 s；
  - 复合类型值（如 `(A -> B)`）、char / boolean 类型值不定义应用解释；
- 解释要点：
  - 覆盖全部跨类型通道，转换全部显式（与《类型系统设计》「类型关系判定的机制」的「无隐式关系、转换显式」一致）；
  - 同类型转换幂等：`int(x)` 当 x 已是 int，产出 x；
  - 收窄越界（如 `byte(256)`）→ 操作无法完成作用 → 诊断值（见后文「操作失败的统一响应」）；
  - `float(x)` 的精度损失不视为失败（决策者显式选择收窄）；
- 必需性：必需——long / float / byte 无直接文本形态（《语法设计》「文本环境对这些值的解释」），没有转换途径则无法获得这些类型的值；数值与字符串的互转是组合覆盖转换方法的必需依赖（《语言结构设计》「类型声明」）。

### 4. 数组

- 形态：`[1, 2, 3]`——方括号文本（绝大多数开发语言的语法使用习惯，《语法设计》「括号与花括号是操作」）；**形态与名字借鉴的是语法使用习惯，不继承任何语言的语义承诺**——Java 数组承诺定长、连续、同质存储，我们没有这些承诺；
- 解释：作用于任意多个值（含 0 个），产出数组值——这些值的**有序聚合**；
- **「有序」的含义**：元素按源代码中的**书写顺序**聚合（书写顺序被保留）——聚合必须有此承诺：若不显式承诺顺序（如无序集合），等于隐式承诺「自动排序」，那是离谱的；有序 = 书写顺序保留，**不是**自动排序；
- 数组的语义承诺 = 有序聚合，**物理表示（连续存储或链式）由环境决定，语义层不承诺**；数组值的可变性由环境定义，本层不预设（与《语言结构设计》「操作构造：lambda」的值可变性同构）；
- **元素访问与长度**：`a[n]`——按书写顺序取第 n 个元素（n 从 0 起），产出该元素的值，n 越界 → 诊断值（见后文「操作失败的统一响应」）；`a.length`——length 字段 = 元素个数（int）；
- 与类型系统衔接：数组类型 = 同质重复形态特例 `int[]`（《类型系统设计》「类型构造操作」）；强类型模式检查元素同质，弱类型模式不检查；聚合本身模式无关（《类型系统设计》「操作解释规则模式无关」），检查是类型系统的介入；
- **容量提示**：`T[N]` 形态（如 `int[10] a = [];`）——类型 `T[]` + 容量提示 N（int 值）；N 是给实现环境的**预计元素量提示**——环境可以据此预留内存，也可以忽略（语义不承诺物理分配：提示是结构，预留是环境的响应）；与 int 精度策略同构（《类型系统设计》「原子类型值」：决策者显式声明、环境响应）；
- 容量提示**可省略**：初始文本已给出元素数时（`int[] b = [1, 2, 3];`），提示冗余——省略是习惯；提示的意义在元素数与预计量不同的情形：空初始化预留（`int[10] a = [];`）、预计增长（`int[5] c = [1, 2, 3];`）；
- 容量提示**不承诺元素数**：数组的语义元素数 = 聚合的值个数，与 N 无关；N 不是「N 个默认元素」（无默认值概念，已决策）；
- 空数组 `[]` 合法；
- 失败情形：无（任意值都可聚合）；
- 必需性：必需——有序聚合是必要功能，没有构造形态，数组值无从产生。

### 5. 字符串操作

- **依托类型**：`at` / `length` 是 **String 类型值的成员**（环境为 String 原子类型提供的类型声明，《语言结构设计》「类型声明」）——String 是类型值（一切皆值），类型值的载荷携带成员（at 是方法、length 是字段，方法与字段值都是值）；成员**不在全局环境绑定表里**——单独写 `at` 时环境查不到绑定（操作名未绑定，《类型系统设计》「失败语义」既有语义），只能经 String 实例获得；
- 形态：`s.at(n)`——at 是**方法**，点号连接操作，紧邻的括号组合 `(n)` 是参数（《语法设计》「文本环境对这些值的解释」第 4 条）；`s.length`——length 是**字段**（成员名后无括号组合），字段访问形态（《语言结构设计》「字段访问」）；
- `s.at(n)` 的解释：接收者 s（String）+ 参数 n（int）——按**字形簇**取 s 的第 n 个字符，产出 char；n 越界、接收者不是 String → 操作无法完成作用 → 诊断值（见后文「操作失败的统一响应」）；
- `s.length` 的解释：接收者 s（String）——产出 s 的长度字段值（按字形簇计数得到的 int）；接收者不是 String → 诊断值（见后文「操作失败的统一响应」）；
- 字形簇**边界划分**是这两个成员的必需依赖；字形簇**排序**是扩展功能，可在后续版本中细化（char 无序——`<` / `>` 不解释 char，char 的相等用 `==`）；
- char 的获得通道：char 不设直接文本，`s.at(n)` 是获得 char 的途径；
- 必需性：必需——char 列入最小清单（《类型系统设计》「原子类型值」），没有 s.at 则 char 无从获得。

### 6. 输出

- 操作名：`print`——应用形态 `print("Hello World!")`（Java 习惯）；
- 解释：作用于一个值，发生作用（把值呈现给决策者——呈现方式由环境决定），产出被输出的值自身；
- 四元落点：操作（环境与决策者之间的边界操作）——值是环境内的抽象，print 使值到达决策者；
- 失败情形：无（任何值都可呈现；呈现的物理方式由环境决定）；
- 必需性：必需——没有 print，解释的结果无法被决策者观察。

## 操作失败的统一响应

- 操作名**已绑定**、作用**无法完成**（除零、溢出等）时，操作产出**诊断值**：操作判定参数无法完成其作用，拒绝并向环境反馈；
- 诊断值沿组合层级向上传递，可被更高层操作捕获或到达决策者（《类型系统设计》「拒绝与诊断」的传递机制）；
- 语义分工（与《语言结构设计》「结构形态总览」/「字段访问」一致）：
  - **操作名未绑定**（名称查找失败）→ **弱类型模式落 Unknown**（核心锚点承载「未解释」）；**强类型模式产生诊断**（检查介入，静态可判定）；
  - **操作认识参数但判定无法完成作用** → **诊断值**——该响应**模式无关**（《类型系统设计》「操作解释规则模式无关」），弱 / 强类型模式下一致；
- 与弱类型模式的关系：「弱类型模式不产生类型诊断」说的是类型诊断——本响应是操作层诊断值，两者不冲突。

## 设计原则（沿用既有文档）

- 每个原子操作过四元自查；
- 解释规则模式无关；
- 最小必要性：操作按需生长（环境可注册新操作，宇宙不封闭）。
