# Origin Language 语法设计

> 定位：语法层 = **文本如何被环境解释为结构**。结构形态由《语言结构设计》定义，本层只定义文本写法。

## 定位与范围

- 语法是「文本 → 结构」的解释，由文本环境提供——环境决定结构如何被解释（《Origin Language 核心抽象设计》「环境」一章）；结构形态（《语言结构设计》「结构形态总览」）为上游，本层不改结构、只定文本；
- 语法**不唯一**：同一结构可有多种文本形态（未来按需生长）；本层先定最小的一套；
- 与既有文档的衔接：
  - 组合、名称引用、原子值的文本写法——对应《语言结构设计》「结构形态总览」；
  - 操作名（`=` / if 等）的文本符号——对应《语言结构设计》「最小操作集合」；
  - 模式声明、expect 的文本形态——落地《类型系统设计》「模式声明的两级形式」/「expect 断言操作」（类型标注已退役——类型直接写在声明位置，《类型系统设计》「类型位置的结构层骨架」）；
  - 工程级声明的文本形式——《类型系统设计》「工程级声明」（`mode(strong);`）。

## 词法：文本环境中的值与操作

> 总则：词法的全部内容落在四元本体论内——不引入「规则」之类的新概念。这里的每一件事，要么是**值**，要么是**操作**（环境提供，操作也是值），要么是**环境的解释**（环境决定值如何被解释，《Origin Language 核心抽象设计》「环境」一章）。

### 1. 空格是操作：连接（边界确立）

- 源代码文本是一串字符，每个字符都是值；
- **空格是操作**（操作也是值）：环境把它解释为「连接」——作用于其左右两侧的文本，确立二者的边界，使它们成为两个可区分的值；
- 文本环境中的原子值 = 被边界确立的一串连续字符（该值在该环境中不可再分）；
- 换行、制表与 `;` 是同一连接操作的其他文本形态，便于多行书写与显式分隔；行首 / 行尾的连接操作一侧无文本，不发生作用；
- `,` 是连接操作的**列表分隔**文本形态：分隔同一层级的元素——数组文本 `[1, 2, 3]`、参数列表 `(int a, int b)`、实参 `f(a, b)`；
- **注释**：`//` 到行尾、`/*` 到 `*/` 之间的文本，环境的解释 = 不产生值（注释是文本，不是结构）——`//`、`/* ... */` 是注释定界操作（Java 习惯）；

### 2. 括号与花括号是操作：定界

- `(` 是操作，作用 = 开启组合；`)` 是操作，作用 = 关闭组合；
- 括号操作作用于其间的内容，使内容成为一个组合——嵌套由此而来：组合的内容可以是组合；
- 括号的三种角色：① 前缀组合——内容为「操作名 + 参数」序列，与 `f(args)` 应用形态同义（语法不唯一，见前文「定位与范围」）；② **分组**——内容为中缀结构时（如 `(x + y)`），该结构被定为一个值参与外层中缀序列（见后文「文本环境对这些值的解释」第 6 条）；③ **参数括号**——值 / 名称后紧邻的括号（`f(a)`、`Person("Jack")`、`s.at(n)`），括号内容是应用的参数；
- `{` 是操作，作用 = 开启顺序结构；`}` 是操作，作用 = 关闭顺序结构；
- `[` 是操作，作用 = 开启数组文本；`]` 是操作，作用 = 关闭数组文本——其间各值（`,` 分隔）聚合为数组值（《语义设计》「数组」）；
- 花括号操作作用于其间的内容：其间各值依次解释——顺序结构（《语言结构设计》「顺序结构」）的文本落点（block 操作名已退役）；花括号可以嵌套：顺序结构的内容可以是顺序结构；
- **类型体区分**：花括号定界的结构，其前相邻的值若是名称，环境先查该名称的绑定——**未绑定 → 类型声明**（类型名 + 类型体，《语言结构设计》「类型声明」）；**已绑定到操作值 → 带体应用**（操作作用于花括号体，如 `try { ... }`，《语言结构设计》「失败捕获」）；花括号不直接跟在名称后时，仍是顺序结构；
- **组合声明形态**：`名称 + 名称 { 体 }`——`+` 在类型声明形态中 = 组合连接（与算术 `+` 是同一操作名，声明位置的环境解释不同，《语言结构设计》「类型声明」）；多组合 `C + A + B { ... }`；
- **类型参数形态**：`Name<T> { 体 }`——`<T>` 在类型声明形态中 = 类型参数声明（《语言结构设计》「类型声明」类型参数）；与比较中缀的区分：位置（声明形态 vs 值位置）；
- **类型实例化**：类型名称后紧邻括号、括号内容为类型值（`Box(int)`）= 类型构造器应用（产出类型值）；内容为普通值（`Person("Jack")`）= 实例构造（《语言结构设计》「实例构造与方法调用」）；
- **转换方法形态**：`T父 __字段名(T子 字段名) { ... }` 与 `T子 __字段名(T父 字段名) { ... }`——双向视角适配器：方法名 `__字段名`、参数名与字段同名、参数 / 返回类型区分方向（《语言结构设计》「类型声明」覆盖）；
- **「操作名(参数) { 体 }」形态**：名称后紧邻参数括号、再紧邻花括号（`if (cond) { ... }`、《语言结构设计》「条件：if」；`while (cond) { ... }`、《语言结构设计》「循环」；`mode(strong) { ... }`、《类型系统设计》「区域级声明」；`expect(T) { ... }`、《类型系统设计》「expect 断言操作」）——环境解释 = 该操作作用于（参数，花括号体）；
- **增强 for 形态**：`for (类型 名称 : 数组值) { 体 }`——for 的参数括号内容 = 参数声明 + `:` + 数组值（《语言结构设计》「循环」）；
- **函数声明区分**：`[返回类型] 名称(参数声明...) { 体 }` 形态中，参数括号内容以类型值开头、其后紧跟名称（如 `int a`）→ **函数声明**（声明即绑定，《语言结构设计》「操作构造：lambda」）；否则 → 带体应用；
- **构造器声明区分**：类型体内，`名称(参数声明...) { 体 }` 且**名称 = 该类型名**（无返回类型）→ **构造器声明**（可重载，《语言结构设计》「类型声明」）；名称 ≠ 类型名 → 方法声明（无返回类型）；

### 3. 文本环境对这些值的解释

上述值被边界确立后，文本环境对它的解释：

1. 以数字开头的值：解释为整数（数字序列）或浮点（数字序列 + 一个小数点 + 数字序列）；整数与浮点的类型归属（int / double）由类型系统环境解释（《类型系统设计》「原子类型值」）；
2. 被引号定界的值：引号是与括号同构的**定界操作**（开启 / 关闭），其内容解释为字符串；
3. 其余的值：解释为**名称**，环境的响应 = 查找绑定（《语言结构设计》「结构形态总览」）——`true` / `false` 除外（第 8 条）；
4. 点号（`.`）是**连接操作**（操作也是值）：作用于左侧的值结构与右侧的成员结构，体现「值 → 内部成员」的连接性；以数字开头的值里，小数点仍属浮点形态的一部分（第 1 条）；
   - `v.name`（成员名后无紧邻括号组合）→ 环境的解释 = **字段访问**：字段名操作作用于值 v，产出字段值（《语言结构设计》「字段访问」）；
   - `v.name(args)`（成员名后紧邻括号组合）→ 环境的解释 = **方法调用**：成员名操作作用于值 v，经 v 携带的类型值取出方法并绑定接收者，再应用于括号组合中的参数（《语言结构设计》「实例构造与方法调用」）；
   - 紧邻 = 点号右侧成员名与括号组合之间无连接操作（无空格 / `;` / 换行，见前文「空格是操作」）；有连接操作时二者是两个值，不构成成员调用；
   - 成员**依托值存在**，不进入全局绑定表（单独写 `at` 时环境查不到绑定）。
5. `=` 是**绑定操作名**（符号名）：绑定结构形态 `[类型] 名称 = 值结构;`（类型可省略）——`;` 是连接操作（见前文「空格是操作」）：结构以 `;` 结尾，多个结构由 `;` 分隔连接（最后结构的 `;` 一侧无文本）；环境的解释 = 绑定操作作用于（名称，类型值（若给出），值结构的解释结果），名称绑定到该值（《语言结构设计》「绑定」）；`=` 与比较操作 `==` 是两个名称（两个绑定），互不相关。
6. 中缀操作与解释顺序：符号操作名 `+` `-` `*` `/` `==` `<` `>` 是**中缀连接操作**——作用于左右两侧的值结构（`x + y`、`a == b`）；环境对中缀序列的解释顺序（从高到低）：① `.` 成员访问（含紧邻参数括号）；② `*` `/`；③ `+` `-`；④ `<` `>`；⑤ `==`；⑥ `=` 绑定；⑦ `->` lambda 箭头；同级从左到右；括号分组（见前文「括号与花括号是操作」②）改变解释顺序；`->` 的 lambda 形态 = `(参数列表) -> 体`（《语言结构设计》「操作构造：lambda」）。
7. `[]` 是**类型构造操作名**（后缀形态）：类型值后紧邻 `[]`（如 `int[]`）= 数组类型——环境的解释 = 类型构造操作作用于类型值，产出数组类型值（同质重复形态，《类型系统设计》「类型构造操作」）；与数组文本区分：`[` 在前（`[1, 2, 3]`）= 数组值，`[]` 在后（`int[]`）= 数组类型；类型值后 `[N]`（`int[10]`）= 数组类型 + **容量提示** N（《语义设计》「数组」，提示可省略）；
8. `true` / `false`：环境直接解释为 **boolean 原子值**（文本直接解释，不查名称绑定）——与数字文本同族（第 1 条）；
9. **数组元素访问**：`v[n]`——值位置的数组值后紧邻方括号 = 按书写顺序取第 n 个元素（n 从 0 起，《语义设计》「数组」）；数组值后 `.length` = 长度字段（元素个数）；与容量提示的区分以**位置**为主判据：**声明位置（`=` 前）的 `T[N]` = 容量提示；值位置的 `v[n]` = 元素访问**。

### 4. 为什么不设「规则」

「规则」不是四元之一。上述全部内容落在四元内：字符是**值**，被边界确立的文本也是**值**；空格、逗号、括号、花括号、方括号、引号、点号、`=`、中缀符号是**操作**；对这些值的解释是**文本环境的解释**。引入「规则」作为独立概念没有必要性，故不引入。

## 文本 → 结构的解释

### 1. 组合与应用的文本落点

- `(` 开启、`)` 关闭；括号之间的值形成组合；
- 组合解释（第一个位置的值被环境解释后若是操作值，则作用于其余位置的值）已由《语言结构设计》「结构形态总览」定义；
- **应用形态**：值 / 名称后紧邻的括号 = 应用——`f(a, b)`（操作值应用）、`Person("Jack")`（类型值应用 = 构造 / 转换）、`s.at(n)`（成员方法）；`f(args)` 与 `(f args)` 是同一应用的两种文本形态（语法不唯一，见前文「定位与范围」）；
- **分组**：括号内容为中缀结构（如 `(x + y)`）时，该结构被定为一个值参与外层中缀序列（见前文「文本环境对这些值的解释」第 6 条）；
- 嵌套：括号之间的值可以包含被括号界定的组合，环境的解释递归进行。

### 2. 操作名的文本

- `=`（绑定）、if / try / catch / while / for / mode / expect / load / return 都是**名称**（见前文「文本环境对这些值的解释」第 3 条），环境经查找绑定得到操作值；lambda 与 block 已退役——lambda = `(参数列表) -> 体` 箭头形态（同前第 6 条），顺序 = 花括号结构（见前文「括号与花括号是操作」）；
- 成员访问（字段 `p.name`、方法调用 `s.at(n)`）经**点号连接操作**解析（同前第 4 条）：点号左侧名称查找得到实例值，右侧成员名取出字段，或经实例携带的类型值取出方法并绑定接收者、应用于紧邻括号组合中的参数（《语言结构设计》「字段访问」/「实例构造与方法调用」）；
- 不存在「关键字」：操作名与普通名称无别——`else` 也是名称（if 的假分支连接，《语言结构设计》「条件：if」）。

### 3. 模式声明的文本

- 工程级：`mode(strong);`——应用形态（名称后紧邻参数括号）+ 分号，入口文件顶层第一个值（见后文「工程级声明」）；
- 区域级：`mode(strong) { ... }`——「操作名(参数) { 体 }」形态（见前文「括号与花括号是操作」）；
- expect：`expect(T) { ... }`——同族形态（见前文「括号与花括号是操作」）；
- 载入传入：`load(link, weak)`——应用形态，载入外部脚本并传入解释模式（《类型系统设计》「传入式调用」，此机制可在后续实现中扩展）。

### 4. 顶层：整段文本 = 一串值

- 整段文本被环境解释为一串按顺序相邻的值；环境对它们**依次解释**，产出最后一个值的解释结果；
- 顶层的依次解释与顺序结构（《语言结构设计》「顺序结构」）是同一种作用（顺序）的两个落点：顺序结构是结构内部的显式形态；顶层的依次解释是文本环境对整段文本的解释；
- 依次解释中某个值解释失败：诊断到达决策者（顶层无更上层环境可传递）——失败语义见后文「失败语义」；
- **入口（main）**：顶层绑定的名称 `main`（操作值）是程序的入口约定——形态可用函数声明 `main(String[] args) { ... }`（无返回 = 返回类型省略）或 lambda 绑定 `main = (String[] args) -> { ... };`（lambda 形态同样要求体无 return，《工程层设计》「main 入口」）——**编译执行**：顶层依次解释后，环境识别 main 并**自动应用**（参数 = 命令行参数序列）——main 是程序执行起点；**解释执行**：顶层依次解释，main 是普通名称（普通绑定，不特殊、不自动应用）；两种执行方式由工程层选择，唯一差别 = 是否在顶层解释完成后自动应用 main（《工程层设计》「两种执行方式」），不改变源代码结构（结构保持、环境响应）。

### 5. 工程级声明

- 形式：`mode(P);`——应用形态 + 分号，位于**入口文件顶层第一个值**；
- 与区域级声明的区分：带花括号体的 mode = 区域级声明（`mode(P) { ... }`，《类型系统设计》「区域级声明」）；单参数带分号的 mode = 工程级声明——两者以形态区分，不需要额外约定；
- 解释：环境依次解释顶层值时，第一个值若是 `mode(P);`，把它解释为工程级声明（环境构造，不产出值）；策略生效后，后续值按该策略解释（P12：运行中不可再切换）；
- 缺省：无声明 = 弱类型模式（《类型系统设计》P4）；
- 位置约束：工程级声明出现在非入口文件或非第一个位置——产生诊断；「入口文件」由载入环境界定（《工程层设计》「入口文件」）；
- 工程级声明不产出值：顶层依次解释的产出 = 最后一个值的解释结果。

## 失败语义

- 文本环境对无法解释的文本产生**诊断值**：诊断是环境向决策者的反馈（组合 / 操作 / 值三视角，《类型系统设计》「拒绝与诊断」），不专属于类型系统；
- 无法解释的情形：以数字开头的值不符合整数 / 浮点形态（如 `123abc`）；括号不配对；引号不配对；
- 与模式无关：语法失败发生在文本 → 结构的解释阶段——结构尚未形成、类型系统尚未介入，弱 / 强类型模式下行为一致；
- 顶层依次解释中某个值解释失败：诊断到达决策者（顶层无更上层环境可传递，见前文「顶层」）。

## 设计原则（沿用既有文档）

- 结构保持、环境响应：语法只负责文本的解释，不改变结构语义；
- 最小必要性：不引入结构层没有的形态；额外的文本形态是想要的功能，最小骨架不包含；
- 不引入四元之外的概念：词法与语法中的一切，要么是值、要么是操作（环境提供）、要么是环境的解释（环境决定值如何被解释）——「规则」不是一个独立概念；
- 每个新值 / 新操作过四元自查。
