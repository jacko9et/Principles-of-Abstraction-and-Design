# Origin Language 语言结构设计

> 定位：语言结构层 = 决策者构造源代码所用的最小结构约定——由**语言环境**提供的原子操作与结构形态构成。本文档回答「源代码可以是什么形状」。

## 定位与范围

- 语言结构层是**语言环境**的设计：定义决策者编写结构时使用的最小操作集合与结构形态。
- 四元落点：本层定义的每一个概念（包括每个操作）都必须过四元自查——**该概念**落在值 / 操作 / 环境 / 组合的哪一元，**该概念本身**是不是值（操作本身也是值）。
- 与既有文档的关系：
  - 核心（Unknown 锚点 + compiler 应用接口）：语言结构层不修改核心，只在其上生长；
  - 《类型系统设计》「类型位置 = 可绑定位置」：类型系统引用本层的「可绑定位置」，由本层定义；
  - 语法层（未来）：本层定义「结构形态」，语法层定义「文本如何写成结构」——两层分离。

## 结构形态总览（沿用核心，非新设计）

- 最小源代码 = 一个组合：`(op v1 v2 ...)`——操作作用于值形成的关系结构。
- 原子值由环境提供（整数、字符串、boolean……与《类型系统设计》「原子类型值」的原子类型对应）。
- **名称引用**：结构中出现的裸名称，由环境解释为「在环境绑定中查找」——名称是结构，查找是环境的响应。
- **组合解释**：`(op args...)` 由环境解释为「op 作用于 args」——核心接口 `operation(input)` 在语言层的体现。
- **应用形态 Java 化**：应用 = 值后紧邻参数括号——`f(a, b)`（操作值应用）、`Person("Jack")`（类型值应用 = 构造）、`s.at(n)`（成员方法）；`f(args)` 与 `(f args)` 是同一应用结构的两种文本形态（语法不唯一）；中缀操作（`+ - * / == < >`、绑定 `=`、成员访问 `.`）作用于两侧的值结构（《语法设计》「文本环境对这些值的解释」第 6 条）。
  - **操作位**：组合首位置的结构先被环境解释；若产出**操作值**，该操作值作用于其余参数——名称（经环境查找得到操作值）只是操作位的最简单情形；
  - **应用不是独立的操作**：它是组合的固有解释规则——把核心接口重复发明为独立操作违反最小抽象；
  - 操作位解释后**未产出操作值**：弱类型模式落 Unknown（名称查找失败等，《语义设计》「操作失败的统一响应」），强类型模式产生诊断——与既有失败语义衔接，无新规则。

## 最小操作集合

### 1. 绑定：=，无返回的环境变动操作

- 形式示意：`int x = 1;`——绑定结构 = `[类型] 名称 = 值结构;`（`=` 是绑定操作名，符号名，《语法设计》「文本环境对这些值的解释」第 5 条；`;` 是结构分隔的连接操作）；类型可省略（弱类型模式无类型绑定：`x = 1;`），强类型模式必须显式类型（《类型系统设计》「类型强制策略」边界显式）；
- 四元落点：`=` 是**操作**（语言环境提供的原子操作），作用于（名称，类型值（若给出），被解释后的值）；绑定本身是值（操作也是值）；
- 作用对象是**环境**：绑定的效果 = 构造/更新当前环境的名称绑定——《Origin Language 核心抽象设计》「源代码」一章「源代码构造环境」在最小尺度上的体现；
- **产出：无**——绑定是纯环境变动操作，不产出传递值（函数类型形态 = 返回类型位置省略，衔接《类型系统设计》「类型构造操作」）。
  - 本层不保留「返回绑定值」或「返回名称」的设计：前者需说明返回的是哪个值，且其语义可被名称引用替代；后者会混淆符号与值。无返回是更稳妥的选择。
- **名称引用**：绑定之后，结构中的裸名称由环境解释为「查找绑定」——名称是结构，查找是环境的响应（见前文「结构形态总览」）。
- 与类型系统的接口：`=` 左侧的名称是「可绑定位置」之一（《类型系统设计》「检查对象」名称绑定）；类型在声明结构里（`int x`，与类型体字段声明同族，见后文「类型声明」），类型位置与绑定结构分离（《类型系统设计》「类型位置的结构层骨架」）；
- 模式无关（《类型系统设计》「操作解释规则模式无关」）：绑定操作在两模式下的解释规则相同。

**绑定可变：重绑 = 重赋**：

- **同名重绑 = 覆盖（重新赋值）**：形式统一，不设独立 set——环境查不到名称 = 定义，查得到 = 重赋（符合主流习惯）；重赋形态 `x = 2;`（类型已声明，无需重复）；
- **载荷相同的重绑不检测**：载荷相同的覆盖无害（仅冗余）；检测需要运行时比较两个值的载荷（先判可区分性，可区分时再比载荷，《语义设计》「比较操作」），不为无害冗余引入复杂度；
- 与类型系统衔接：强类型模式下重赋的新值必须通过已绑定名称的声明类型检查（《类型系统设计》「检查对象」操作调用判定）；弱类型模式不检查——类型安全不因可变绑定受损；
- 可变绑定与统一重绑定形式保持一致，符合常见使用习惯；同时仍保持解释的确定性，即同一结构在同一解释环境下具有稳定结果。

### 2. 操作构造：lambda，产出操作值

- 形式示意：`(int a, int b) -> body`——参数列表（`类型 参数名`，逗号分隔）+ `->`（箭头连接操作，《语法设计》「文本环境对这些值的解释」第 6 条）+ 体（单个结构，或花括号块 `{ s1; s2; }`）；
- 四元落点：lambda 是**操作**（语言环境提供），其作用是**构造一个操作值**——lambda 本身是值，产出也是值。
- **构造时不求值体**：参数结构与体结构被保留在操作值里，体在「应用」时才被解释——体是结构，应用时环境才解释它（结构保持、环境响应）。
- **产出 = 操作值**：与绑定（无返回）不同，lambda 是构造器；操作值随后由绑定操作（见前文「绑定」）绑定到名称——操作构造与名称绑定分离。
- **解释环境：携带构造时的环境**——lambda 值携带构造时的环境，应用时在携带的环境中解释体。
  - 本体论依据：环境也是值（外部观察者视角），lambda 值 = 参数结构 + 体结构 + 构造时环境；
  - **携带 = 共享**：携带的是构造时的**环境值本身**——应用时在该环境值中查找绑定；构造之后对同一环境的重绑，应用时可见；
  - 这里排除按调用链查找绑定的解释方式，因为这种解释依赖调用链，导致行为不可预测，并与确定性要求相冲突。
- 参数是「可绑定位置」（《类型系统设计》「检查对象」）：参数类型进声明位置（`int a`，与字段声明同向，《类型系统设计》「类型位置的结构层骨架」）；强类型模式下必须显式类型（「类型强制策略」边界显式），弱类型模式类型可省略（`(a, b) -> body`）；返回类型不写，由体的 `return` 值决定（见后文「返回」）；
- **lambda 绑定的类型**：由 lambda 自身确定——参数类型已写在参数列表、返回类型由体的 return 决定；`twice = (int n) -> n * 2;` **不需要另写类型位置**（强类型模式同样成立：类型来自 lambda 自身，不是推导——《类型系统设计》「类型强制策略」边界显式的 lambda 特例）；
- 模式无关（《类型系统设计》「操作解释规则模式无关」）。
- 必需性：必需——操作是值，无法构造新操作值则语言无法生长。

**函数声明（具名函数）**：

- 形式示意：`int add(int a, int b) { return a + b; }`；无返回 = 返回类型省略：`doSomething(int a) { a + 1; }`（体无 return，各结构依次解释）；
- 形态与方法声明同族（见后文「类型声明」）：`[返回类型] 名称(参数声明...) 体`——位置区分：类型体内 = 方法声明，结构层（顶层 / 顺序结构内）= 函数声明；
- 声明即绑定：函数声明自带名称绑定（与类型声明 `Person { ... }` 同族），不另经 `=`；
- 与 lambda 的分工：函数声明 = 具名函数；lambda = 匿名函数值（可绑定、可传递）——`int add(int a, int b) { return a + b; }` 与 `add = (int a, int b) -> a + b;` 语义等价（语法不唯一，《语法设计》「定位与范围」）；
- 区分规则：参数括号内容以类型值开头、其后紧跟名称（`int a`）→ 函数声明；否则 → 带体应用（if / mode / expect，《语法设计》「括号与花括号是操作」）；
- 四元落点：结构（环境的解释 = 构造操作值 + 绑定名称），零新类别；
- 与类型系统衔接：强类型模式参数类型必须显式（「类型强制策略」边界显式）；返回类型省略 = 无返回（体不 return）；
- 模式无关（《类型系统设计》「操作解释规则模式无关」）。

**参数可重新赋值**：参数名绑定在应用时构造的**局部环境**中；重赋参数名只改变该局部环境中的绑定关系，不影响调用方环境。

- 绑定关系 = 环境中的「名称 → 值」关系。应用 `f(a)` 时：实参结构 a 被环境解释得到值，局部环境建立「参数名 x → 该值」的关系；若 a 是名称且已绑定该值，则调用方环境与局部环境的两条关系中出现的是**该值**——该值出现在多条关系中，仍是它自身；
- 两条关系中的值是否可区分，由环境的区分策略判定（《Origin Language 核心抽象设计》「值」一章：值必须能被区分，区分策略由环境提供）；
- **重赋参数名**（如 `x = 2;`）：局部环境中「x → 值」的关系改指新值——该关系改变；调用方环境中 a 的关系不受影响；值的自身状态不被绑定关系的改变所改变；
- **值的可变性**：核心抽象设计未规定值是否可变、变化前后是否可区分——由环境的区分策略判定；本层的绑定语义不预设答案，只陈述「名称 → 值」关系及其改变。

### 3. 字段访问：字段名即操作

- 形式示意：`point.x`——点号**连接操作**（《语法设计》「文本环境对这些值的解释」第 4 条）：字段名本身就是一个访问操作，作用于聚合结构值，产出该字段的值；**不引入统一的 get 操作名**；
- 四元落点：每个字段名是**操作**（语言环境提供的原子操作），作用于聚合结构值，产出字段值；字段名不是全局绑定表中的操作名——它是**成员名**，只经点号连接操作进入解释（成员依托值存在，不能单独出现）；
- 与类型系统衔接：《类型系统设计》「类型构造操作」「字段名 = 操作名」——结构形态类型里的字段名就是本层的访问操作；强类型模式下字段访问的检查 = 操作调用判定（「检查对象」第二类）。
- 失败语义：访问不存在的字段 → 弱类型模式落 Unknown（成员名未绑定，《语义设计》「操作失败的统一响应」），强类型模式产生诊断——与既有失败语义一致。
- **成员方法依托类型值**：类型也是值（《类型系统设计》「类型宇宙的骨架」），成员方法（操作也是值）在类型值的载荷里（《类型系统设计》「原子类型值」）；成员名操作作用于**实例值**时，经实例值携带的类型值（类型运行时保留，《类型系统设计》「类型值在运行时保留」）取出方法——成员解析与本机制同构：成员名是操作，作用于实例值，产出绑定接收者的方法操作值（见后文「实例构造与方法调用」）。
- 模式无关（《类型系统设计》「操作解释规则模式无关」）。
- 必需性：必需——聚合结构必须能取出部分值，否则组合只能整体传递、内部无法使用。

### 4. 条件：if，惰性选择性解释

- 形式示意：`if (cond) { ... } else { ... }`——`(cond)` 是条件括号结构，`{ ... }` 是分支块（顺序结构，见后文「顺序结构」），`else` 连接假分支；else 可选：无 else 且条件为假 → 产出「无」（同绑定无返回）；
- 四元落点：if 是**操作**（语言环境提供的原子操作），作用于（条件结构，真分支结构，假分支结构（若有））。
- **惰性选择**：if 只解释被选中的分支，另一分支不被解释——这是 if 的存在理由：若两分支都解释，条件就失去意义。
- **特殊操作的资格**：if 与普通应用解释（参数先全部解释）不同——它**选择性解释分支**。
- 条件的真伪判定：由 if 的解释规则规定（解释条件结构后按环境约定判定真伪）——宽松行为属操作自身，不是类型系统的机制（《类型系统设计》『弱』的定性 操作自行解释）。
- 与类型系统衔接：强类型模式下 if 的操作声明（条件 boolean、两分支类型一致），检查按《类型系统设计》「检查对象」第二类操作调用判定。
- 模式无关（《类型系统设计》「操作解释规则模式无关」）。
- 必需性：必需——没有分支，结构无法表达「按条件选择」的关系。

### 5. 顺序结构：花括号结构，依次解释

- 形式示意：`{ s1; s2; ... }`——花括号定界（《语法设计》「括号与花括号是操作」），其间各结构依次解释，产出**最后一个**结构的解释结果（前面结构的作用已发生，结果被丢弃）；block 操作名退役（花括号是顺序结构的唯一形态）；
- 四元落点：顺序结构是**结构**，环境的解释 = 依次解释（环境的响应）；
- **为什么必需**：绑定无返回的设计要求顺序结构承接后续计算（`{ int x = 1; x * 2 }`）；没有顺序结构，绑定后的计算就无法继续表达。
- **特殊解释**：顺序结构依次解释、只保留最后结果——与「参数先全部解释」的普通应用不同。
- 失败语义：中间某结构解释失败 → 诊断值沿组合层级向上传递，后续结构不再解释——诊断的影响范围收窄到最近的环境，由该环境终止对失败结构的本次解释（《类型系统设计》「拒绝与诊断」同构）。
- 模式无关（《类型系统设计》「操作解释规则模式无关」）。
- 必需性：必需——绑定无返回的配套结构，否则「定义后计算」无法表达。

### 6. 最小操作集合汇总

| 操作 | 形态示意 | 四元落点 | 产出 | 备注 |
|---|---|---|---|---|
| 绑定 | `int x = 1;` | 操作（环境变动） | 无 | 取值由名称引用完成 |
| 操作构造 | `(int a) -> body` | 操作（构造操作值） | 操作值 | 携带构造时环境，参数自带类型 |
| 函数声明 | `int add(int a, int b) { return a + b; }` | 结构（构造操作值 + 绑定） | 无 | 与方法声明同形态，声明即绑定 |
| 字段访问 | `point.x` | 操作（字段名即操作） | 字段值 | 点号连接操作，无统一 get |
| 条件 | `if (cond) { ... } else { ... }` | 操作（惰性选择） | 被选分支结果 | 特殊操作，else 可选 |
| 顺序 | `{ s1; s2; }` | 结构（依次解释） | 最后结构结果 | block 已退役 |
| 类型声明 | `Person { String name; ... }` | 结构（环境解释 = 构造类型值 + 绑定） | 类型值 | 字段 + 方法；组合 `B + A`、泛型 `Box<T>` |
| 实例构造 | `Person("Jack")` | 类型值可应用（环境承诺） | 实例值 | 与数值转换同一机制 |
| 方法调用 | `s.at(n)` | 点号连接 + 应用 | 方法结果 | 接收者在点号左侧 |
| 失败捕获 | `try { ... } catch (e) { ... }` | 操作（选择性解释） | 无（结构） | 特殊操作，e 绑定诊断值 |
| 返回 | `return v;` | 操作（终止体的解释） | v 的值 | 特殊操作，方法 / lambda 体产出 |
| 循环 | `while (cond) { ... }` / `for (int x : a) { ... }` | 操作（重复解释） | 无 | 特殊操作，计数 for 可在后续版本中细化 |

- 应用：不是新操作——组合解释的固有规则（见前文「结构形态总览」）；应用形态 `f(args)`（值后紧邻参数括号）；类型值可应用 = 数值类型转换（《语义设计》「转换：类型值可应用」）或结构类型实例构造（见后文「实例构造与方法调用」）——环境对类型值位于应用位置的解释承诺。
- 特殊操作资格：只有「不按『参数先全部解释』规则解释」的操作（if 惰性选择、顺序结构依次解释、try 选择性解释）才需要特殊处理。
- 绑定可变：同名重绑 = 覆盖（重赋），统一形式不设 set；载荷相同的重绑不检测；参数可重赋（局部环境关系变动，不影响调用方）；值的可变性由环境定义，本层不预设（见前文「操作构造：lambda」）。

### 7. 类型声明：`Name { ... }`，构造并绑定类型值

- 形式示意：
  ```
  Person {
    String name;
    int add(int a, int b) { return a + b; }
    String greet() { return this.name; }
  }
  ```
- 整体形态：`Person { ... }` = 类型名 + 花括号**类型体**——环境对「名称 + 花括号」相邻结构的解释 = **类型声明**：构造**类型值**（类型是值，《类型系统设计》「类型宇宙的骨架」）并把名称 Person 绑定到它——声明自带绑定，不另经绑定操作；类型名因此是普通名称，实例构造（见后文「实例构造与方法调用」）与成员访问（见前文「字段访问」）经名称查找得到类型值；
- 四元落点：类型声明是**结构**，环境的解释 = 构造类型值 + 绑定（环境变动）；花括号是定界操作（《语法设计》「括号与花括号是操作」，含类型体 / 顺序结构的区分规则）；零新类别；
- **类型体** = 声明列表：其间各声明依次被环境解释为类型值载荷的成分（与顺序结构不同——产出是类型值的载荷，不是最后结构的解释结果）；
  - **字段声明** = `类型 字段名`（`;` 分隔——`;` 是连接操作，《语法设计》「空格是操作」）——对应 `String name;`；与《类型系统设计》「类型构造操作」结构形态类型同构（字段名 = 操作名）；
  - **方法声明** = `[返回类型] 方法名(参数声明...) 方法体`——无返回 = 返回类型省略（与函数类型「无返回 = 返回类型位置省略」同构，《类型系统设计》「类型构造操作」）；参数声明 = `类型 参数名`（与字段声明同向）；
  - **构造器声明** = `类型名(参数声明...) 构造器体`——无返回类型、名称 = 类型名（与方法的区分）；允许**构造器重载**（按参数声明匹配）；体 = 结构序列，字段初始化用 `this.字段名 = 值;`；
  - **方法体** = 花括号顺序结构（《语法设计》「括号与花括号是操作」），结构分号结尾：应用时按顺序结构语义依次解释；**有返回类型的方法：体必须经 `return v;` 产出**（体解释完未 return → 诊断值，《语义设计》「操作失败的统一响应」）；无返回类型的方法：体不需要 return（各结构依次解释，产出无）；
- **方法体的解释环境**：实例环境 = 局部环境（与见前文「操作构造：lambda」参数重赋的环境构造同构），绑定 = `this → 接收者实例` + `参数名 → 参数值`；字段访问经 `this.name`（见前文「字段访问」）——接收者显式，不设隐式字段可见；
- 与类型系统衔接：强类型模式下字段类型与方法声明（参数 / 返回类型）是类型值，检查在实例构造（见后文「实例构造与方法调用」）与方法调用（见后文「实例构造与方法调用」）处按操作调用判定（《类型系统设计》「检查对象」第二类）；字段 / 方法参数 / 返回是「可绑定位置」（《类型系统设计》「类型位置 = 可绑定位置」）；
- 模式无关（《类型系统设计》「操作解释规则模式无关」）；
- 必需性：必需——类型是值，没有声明携带字段与方法的类型值的形态，名义类型与成员操作无从生长。

**组合声明：`Name + 父类型... { ... }`**：

- 形式示意：
  ```
  A {
    String name;
    int id;
  }

  B + A {
    int age;
  }
  ```
- 形态：`B + A { ... }`——类型名 + `+` 组合连接 + 父类型名 + 类型体（多组合：`C + A + B { ... }`）——B 组合 A：**A 的全部成员（字段与方法）提升进 B**（`b.name`、`b.show()` 直接可用）；组合是四元本体论的核心概念——复用即组合：继承、独立接口声明、独立复合声明**三者合二为一进组合**（不引入继承；「接口」只是含无体方法的类型声明；「可替换」只是组合声明的名义推论）；
- **声明顺序贯穿三处**：成员归属、构造参数顺序、冲突解决（一套顺序三处使用）；
- **构造参数顺序** = 类型声明的从左到右：自身字段按声明顺序 → 组合成分的未覆盖字段（按组合声明顺序）——`B(18, "Jack", 42)` 对应 B 的 age → A 的 name、id；
- **覆盖**：类型体显式声明同名成员 → 覆盖父类型同名成员：
  - **构造器参数只收子结构字段**——被覆盖的父字段不占参数位置；
  - 被覆盖的父成分字段由子结构字段维护——**同类型覆盖：值直接共用**（无需转换）；**异类型（冲突）覆盖：经双向转换方法**（视角适配器，按需提供）：
    - **子 → 父**：`T父 __字段名(T子 字段名) { ... }`——构造时填充父成分字段，之后子字段重赋时同步；父视角（A 类型位置）取值用它；
    - **父 → 子**：`T子 __字段名(T父 字段名) { ... }`——子视角取值用它：**子结构类型的名称接收父结构实例**（`B b = a;`）时，b 的该字段经它从父实例转换；
    - 方法名 = `__` + 字段名，参数名与字段同名，参数 / 返回类型区分方向；缺失对应方向 → 诊断；
  - **子结构类型的名称接收父结构实例**（`B b = a;`）：B 的提升成员（来自父类型）可用；B 自身声明的字段无值（访问 → 强类型模式产生诊断 / 弱类型模式落 Unknown，《语义设计》「操作失败的统一响应」）；
  - 同名同类型的多父字段：不强制声明，按组合声明顺序先声明者生效；
  - **同名异类型的多父字段且子类型未覆盖**：成员提升冲突——环境无法构造该类型值 → 诊断值（模式无关，《语义设计》「操作失败的统一响应」「认识但无法完成作用」）；消歧方式 = 子类型显式声明该字段（覆盖）；
- **可替换资格**：父类型含无体方法（接口方法，见下条）时，`Dog + Animal` 的组合声明同时 = **名义声明 Dog 实现 Animal**——Dog 显式声明实现全部无体方法后，**Dog 可用于 Animal 类型的位置**（参数 / 名称绑定 / 返回）；参数位置判定：v 的类型 = T，或 v 的类型组合声明了 T——**直接或沿组合链传递**（`C + B`、`B + A` ⇒ C 对 A 成立）——且 T 的无体方法在 v 的类型中全部有实现（实现可来自成员提升；名义、静态可判定，非结构推导）；运行时方法调用经实例携带的类型值找到方法实现（天然成立）；`expect(T)` 判定同步（《类型系统设计》「expect 断言操作」）；
- **无体方法**：方法声明无体（`String name();`）= 接口方法（接口即含无体方法的类型声明，无独立接口概念）——该类型不可实例构造：强类型模式构造时静态检查拒绝（诊断）；弱类型模式不阻止构造，调用无体方法 → 操作认识方法但无实现体、无法完成作用 → 诊断值（《语义设计》「操作失败的统一响应」）；
- 四元落点：组合声明是**结构**（环境的解释 = 构造组合类型值 + 绑定），零新类别；
- 必需性：想要的功能（成员复用）——组合是核心已有概念，成员复用必须有一种形态。

**类型参数（泛型）**：

- 形式示意：
  ```
  Box<T> {
    T value;
    T get() { return this.value; }
  }
  ```
- 声明：`Name<T> { ... }`——`<T>` 声明类型参数（T 在类型体内是类型值，可作字段 / 参数 / 返回的类型位置）；
- 实例化 = **类型值可应用**（与 `Person("Jack")` 同一机制）：`Box(int)`——名称后紧邻参数括号、括号内容是**类型值** → 产出新类型值（类型构造器应用）；括号内容是普通值 → 实例构造——按参数是类型值还是值区分；
- 实例构造：`Box(int)(42)`——先实例化类型再构造实例；参数检查符合 T（`Box(int)("a")` → 诊断）；
- 嵌套自然成立：`Box(Box(int))`、`Box(int)[]`；
- 四元落点：类型参数是名称（值）；实例化 = 类型值可应用（环境承诺）；零新类别；
- 必需性：想要的功能（类型参数）——类型构造器机制提供了这一形态的落点。

### 8. 实例构造与方法调用：类型值可应用

- **实例构造**：`Person("Jack")`——名称 Person（查绑定得类型值）后紧邻参数括号，**类型值可应用**：类型值应用于值 = 构造该类型的实例，产出实例值；**有显式构造器 → 按构造器的参数声明匹配**（无匹配 → 诊断值）；**无显式构造器 → 参数按字段声明顺序对应**（组合类型的字段顺序见前文「类型声明」声明顺序）；
- **与数值转换同一机制**：类型值可应用——数值类型应用 = 转换（《语义设计》「转换：类型值可应用」），结构类型应用 = 实例构造；应用类型值 = 产出该类型的值；
- 参数个数 / 类型与字段声明不符 → 操作无法完成作用 → 诊断值（《语义设计》「操作失败的统一响应」统一响应）；
- **方法调用**：`s.at(n)`——点号连接操作（《语法设计》「文本环境对这些值的解释」第 4 条）：成员名操作 at 作用于点号左侧的实例值 s，经 s 携带的类型值取出方法，产出**绑定接收者 s 的方法操作值**；紧邻的括号组合 `(n)` 中的参数应用于该操作值——接收者在点号左侧（s），参数在括号里（对应 Java 的 s.at(n)）；
- **方法操作值的应用规则**：方法值 =（方法声明，实现体，接收者）——只经 `s.at` 解析获得，接收者恒为 s；方法值应用于参数 = 在实例环境解释实现体（实例环境 = this + 参数绑定，见前文「类型声明」）；参数类型不符 → 诊断值；
- 四元落点：类型值（值）位于应用位置、环境对它的应用解释（环境承诺）——应用是组合的固有解释（见前文「结构形态总览」），类型值可应用是环境对该解释的扩展承诺；不引入新类别；
- 模式无关（《类型系统设计》「操作解释规则模式无关」）；
- 必需性：必需——类型声明（见前文「类型声明」）产出类型值，没有实例构造则类型值只能出现在声明位置、不能产生该类型的值。

### 9. 失败捕获：try / catch，结构形态

- 形式示意：
  ```
  try {
    10 / 0;
  } catch (e) {
    print("failed");
  }
  ```
  ——try 是**结构**（Java 习惯）：块内是结构序列（分号结尾）；`catch (e)` 是捕获分支（e 绑定诊断值）；
- 四元落点：try 是**操作**（语言环境提供的原子操作），作用于（被保护块结构，捕获分支结构）；诊断值是**值**（《语义设计》「操作失败的统一响应」），可被绑定；
- **动态诊断的处理**：try 块内结构依次解释——块内某结构解释失败（诊断值产生，《语义设计》「操作失败的统一响应」）→ 该块其余结构不再解释，诊断值传给 catch：e 绑定诊断值，catch 块结构依次解释；块全部解释成功 → catch 不解释；
- **产出：无**——结构形态（Java 习惯），出现在顺序结构 / 方法体中；不再作为值结构使用；
- **特殊操作资格**：选择性解释（与 if 同族，见前文「条件：if」）；
- 与类型系统衔接：诊断值不参与类型检查（失败信号不是类型）；
- 模式无关（《类型系统设计》「操作解释规则模式无关」）；
- 必需性：必需——动态解释失败（除零、越界等）必须能在结构内处置，否则诊断值只能一路传播到决策者；
- finally 可在后续版本中细化。

### 10. 返回：return，终止体的解释

- 形式示意：`return v;`——return 是操作名（名称），结构分号结尾（《语法设计》「操作名的文本」）；
- 四元落点：return 是**操作**（语言环境提供的原子操作），作用于值结构 v；
- 解释：终止当前方法体 / lambda 体的解释，产出 v 的解释结果——return 之后的结构不再解释；
- **特殊操作资格**：终止解释操作（与 if / try 同族）；
- 有返回类型的方法 / 函数：体必须经 return 产出（体解释完未 return → 诊断值，《语义设计》「操作失败的统一响应」）；无返回类型：体不需要 return（各结构依次解释，产出无）；
- 与顺序结构的关系：顺序结构依次解释、产出最后结构的结果（见前文「顺序结构」）；return 在其中出现 = 提前终止并产出；
- 模式无关（《类型系统设计》「操作解释规则模式无关」）；
- 必需性：必需——方法 / 函数必须能显式产出结果并提前终止（Java 习惯）。

### 11. 循环：while / for，重复解释

- 形式示意：`while (cond) { ... }`；增强 for：`for (int x : numbers) { ... }`（遍历数组元素）；
- 四元落点：while / for 是**操作**（语言环境提供的原子操作），作用于（条件/参数声明结构，体结构）；
- **while 的解释**：重复解释条件结构——cond 解释为 boolean 真 → 解释体，再判 cond，直到 cond 假；体的每次解释都在当前环境（名称重赋可见）；
- **增强 for 的解释**：作用于（参数声明 `int x`，数组值）——按书写顺序逐元素：每元素建立局部绑定（x → 该元素）并解释体；
- **特殊操作资格**：重复解释（与 if / try / return 同族，见前文「条件：if」/「失败捕获」/「返回」）；
- 与类型系统衔接：while 的 cond 类型 boolean；增强 for 的 x 类型与数组元素类型按操作调用判定（《类型系统设计》「检查对象」第二类）；
- 模式无关（《类型系统设计》「操作解释规则模式无关」）；
- 必需性：必需——遍历数组（配合 `a[n]` 与 `a.length`，《语义设计》「数组」）必须能重复解释结构；
- 计数 for（`for (int i = 0; i < n; i = i + 1) { }`）可在后续版本中细化。

## 设计原则（沿用既有文档）

- 最小必要性：没有定义，不需要证明；定义了，才需要证明它为什么必须存在；
- 显式优于隐式；
- 结构保持，环境响应；
- 操作即适配器：新能力以环境提供的操作形式生长，不引入独立类别；
- 每个新操作先过四元自查，再谈语义。
